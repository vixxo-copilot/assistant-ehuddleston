# Survey grill — decision tree

Ask **one question at a time**. After each answer, state your recommended
default in one line, then move to the next unresolved branch.

Skip any branch already answered in the user's ask or prior turns.

## 1. Decision (start here)

**Q:** What decision will this survey change — what will you do differently
with the answers?

**Recommend:** Tie every question to one decision (ship / kill / prioritize /
message). If they only want "insights," push for the decision behind it.

## 2. Audience

**Q:** Who exactly answers this — role, org boundary, and how many people?

**Recommend:** Narrow to the smallest group that can decide; avoid "everyone
at Vixxo" unless the decision is company-wide.

## 3. Access + identity

**Q:** Internal-only (org account required) or anyone with the link? Named
responses or anonymous?

**Recommend:** Internal + named for operational/staff surveys; anonymous for
sensitive culture/feedback. External link only when respondents are outside
the tenant.

## 4. Success metric

**Q:** What single number or signal means the survey worked?

**Recommend:** One primary metric (e.g. NPS, % "would recommend," top
blocker theme). Secondary questions support that metric — they do not compete
with it.

## 5. Length budget

**Q:** Max minutes to complete, and hard cap on question count?

**Recommend:** ≤5 minutes / ≤8 questions for broad audiences; ≤12 for
specialists who care. Cut before adding.

## 6. Must-ask topics

**Q:** What 2–5 topics must appear even if we cut everything else?

**Recommend:** Map each topic to one question type (see question-types.md).
Merge overlapping topics.

## 7. Question shape

**Q:** Prefer closed (choice/rating/NPS) for scoring, open text for
diagnosis, or a mix?

**Recommend:** Closed first for scoring; one optional open text at the end
for "what did we miss." Avoid walls of open text.

## 8. Demographics / segmentation

**Q:** Do you need role, region, tenure, customer segment, etc. to slice
results?

**Recommend:** Only segment fields you will actually filter on. Put them
last; make optional unless analysis depends on them.

## 9. Timing + distribution

**Q:** When does it open/close, and how will you send it (email, Teams,
QR, embed)?

**Recommend:** Short window (3–7 days) with one reminder. Distribution plan
is separate from form create — do not auto-send.

## 10. Edge cases

Ask only if relevant:

- Quiz / scored form? (default: no)
- File upload needed? (default: no)
- Branching logic? (note for manual designer; auto-create skips branching)
- Existing Form to edit vs brand-new? (this skill creates **new** forms)

## Finish the grill

Summarize:

1. Decisions made (with rationale)
2. Open deferrals
3. Draft survey outline ready for approval → then create
